Overview
We are building a free flashcard learning journey that takes DevOps engineers to Forward
Deployed Engineer (FDE) readiness, with paid hands-on labs added in phase 2. The app
already supports SSO and flashcard creation; this spec covers what to add on top so it
works as a structured, public learning product.
Business model. Learning is free: all decks, reviews and progress tracking cost nothing.
Revenue comes later from paid labs (sandboxed environments where learners build and
get auto-graded) and from team plans. We are not selling a course.
What makes it different. Competitors sell fixed cohorts or video courses. We offer a
DevOps-specific path, spaced repetition so people retain what they learn, judgment-style
scenario cards rather than just definitions, and content that is updated card by card.

Content model
Content is a four-level hierarchy: Track → Phase → Deck → Card. Decks hold 15–25 cards so
one can be finished in a sitting.
Tracks. Two tracks share the same decks: "Learn AI" (Phases 1–6) and "Become an FDE"
(Phases 1–7 plus FDE-tagged cards). A card's track field controls which tracks include it.

1 . Concept: question and answer.
2. Scenario: a situation, then the right response and why.
3. Spot the flaw: a code, config or prompt snippet with a problem to identify.
4. Ordering: drag items into the correct sequence; auto-graded.
5. Choose the approach: multiple choice between approaches; auto-graded.
Concept, scenario and spot-the-flaw cards are self-graded (learner reveals the answer
and rates recall). Ordering and choice cards are graded by the app.

Learning engine
Learners move through the journey by placement, deck study, daily reviews and phase
checkpoints; spaced repetition decides what they see each day.

The loop repeats for each of the seven phases; the paid lab step is a waitlist link until
phase 2.
Spaced repetition. Use FSRS (open-source implementations exist for most languages).
Each self-graded card is rated Again / Hard / Good / Easy; auto-graded cards map correct
→ Good and wrong → Again. Store a review log per learner per card (card_id, card_version,
rating, timestamp, elapsed time) so the scheduler can be re-tuned later.
Daily session. The home screen shows one button: "Start today's session". A session
mixes due reviews first, then new cards from the current deck, capped at a learner-set
limit (default 15 new cards a day).
Placement test. On first sign-in, offer an optional 10–15 minute test sampling each phase.
Phases the learner passes are marked "tested out": unlocked, with their cards added to
review at low priority rather than taught as new.
Gating. Each phase ends with a checkpoint deck of 10–15 mixed scenario cards drawn
from that phase. Scoring 80% or higher unlocks the next phase. Failing shows which decks
to revisit and allows a retry after 24 hours. Admins can turn gating off per track.
Build-it tasks. Each phase ends with a short practical task (for example, "build a read-only
Kubernetes troubleshooting agent"). In phase 1 these are self-reported checkboxes with a
written guide. In phase 2 they become paid, auto-graded labs (see Phase 2 hooks).

Learner reports and per-card analytics flow back to authors, so weak cards get rewritten
through the same pipeline.
1 . Repo layout: tracks/<track>.yaml, phases/<n>/<deck>/deck.yaml (deck metadata)
and phases/<n>/<deck>/cards/*.yaml (one file per card).
2. Authoring: authors open a pull request; at least one reviewer with real-world
experience approves it.
3. CI checks on every PR:
Validate every file against a JSON Schema of the card format.
Check card IDs are unique and never reused from retired cards.
Check every source URL returns HTTP 200 (nightly as well, opening an issue for
broken links).
Warn on cards with last_reviewed older than 90 days.
Lint Markdown and code blocks.
4. Publish on merge: CI calls an authenticated import endpoint, e.g. POST
/api/content/import, with the changed decks. The import is idempotent and
versioned: new cards are added, changed cards get a new version, removed cards are
set to retired (never hard-deleted, so review history survives).
5. Preview: each PR gets a preview link showing the cards rendered as learners will see
them.
The repo may become public later so the community can contribute decks; keep secrets
and lab answers out of it.

Teams, admin and analytics
Teams are the future paid tier, so the data model should support them from day one even
if the UI ships later.
Teams (v1.1)
An organization has teams; a team has members and one or more managers.
Managers see each member's current phase, streak, checkpoint scores and weak
decks. They do not see individual card answers.
Private decks: an organization can add its own decks (e.g., from internal runbooks)
visible only to its members.
CSV export of team progress.
Admin (MVP)
Publish, unpublish and retire decks; see import history.
Card report queue with status (open, fixed, rejected).
User and organization management.
Analytics events (MVP). Track at minimum: signup, placement_completed,
session_started, card_reviewed (with rating and time), deck_completed,
checkpoint_attempted (with score), phase_unlocked, build_task_marked_done,
card_reported, lab_waitlist_joined. Per-card analytics (average rating, Again rate,
report count) should feed back to authors so weak cards get rewritten.
Phase 2 hooks for paid labs
Labs are out of scope for this build, but four things must be in place now so they plug in
without a rewrite.
1 . lab_ref on cards and build-it tasks. Show a "Practice this in a lab — coming soon" link
that adds the learner to a waitlist for that lab.
2. Entitlements table. entitlements(user_or_org_id, product, granted_at,
expires_at, source). In phase 1 everything checks against it and everyone has free;
later, labs_monthly, labs_credits and team_plan are added without touching
feature code.
3. Payments-ready account model. Keep billing identity separate from login identity so
an organization can pay for many users. No payment provider needed yet.

The full scope of each release is listed below.
1 . MVP (pilot): GitHub/Google sign-in alongside SSO; content model and all five card
types; FSRS daily sessions; Phase 1 checkpoint and gating; journey map; streaks and
email reminders; card reporting; Git import pipeline with CI checks; admin basics;
analytics events; lab_ref waitlist and entitlements table.
2. v1.0 (public launch): placement test; Phases 1–6 content loaded; guest preview of the
first deck; PR preview links.
3. v1.1: teams and manager dashboard; private org decks; Slack reminders; interview
mode; Phase 7 content.
4. v1.2: "Ask about this card" AI tutor; public profiles; referrals; groundwork for phase 2
labs.
